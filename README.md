# AI Investment HQ

> **Framework First．Document Driven．Evidence Based．Long-term Thinking**

## 協作與決策架構

AI Investment HQ 採用三層閘門架構：**情報閘門 → 分析閘門 → 對抗閘門**。情報閘門負責來源蒐集與證據整理；分析閘門負責資訊統合、分級、正式分析與輸出草案；對抗閘門負責深度研究、反證檢驗與壓力測試。**CIO 是唯一最終治理裁定者**，所有正式知識、正式文件與重大治理結果均須依既定流程核准。

每日戰情室採 CIO 直送模式：CIO 將全天原始情報放入今日工作區，分析閘門進行去重、事件索引、來源與時間標記、事實／推論／市場情緒區分，並在晚間完成正式情報統合。若涉及投資組合風險或持股水位，戰情室只引用風控官的正式判定，不自行重算或改寫正式風控模型。

資料流圖與整理提案位於 [`docs/99_整理與封存/`](docs/99_整理與封存/)。

## 核心治理原則

AI Investment HQ 遵循以下原則：

1. **Evidence first：** 每項正式結論均須可追溯至官方資料、財報、公司公告、可信市場資料或明確標示的推論。
2. **Separate facts from interpretation：** 事實、分析框架判讀、決策層、行動層與待驗證事項分開呈現。
3. **Decision before narrative：** 正式輸出優先交代影響、燈號、決策層、行動層與觀察條件。
4. **No false precision：** 資料不足時標示「待驗證」或「未評估」，不得用猜測補齊。
5. **Portfolio-aware：** 除非 CIO 明確指定單一帳戶，正式輸出須完整考慮家庭投資中心的已登錄帳戶。
6. **Versioned change：** 長期規則、分析框架與正式流程的變更，須同步更新版本紀錄與受影響文件。

## Repository 使用規則

本 Repository 不永久保存臨時聊天內容。整理草稿、歷史版本、已撤回提案與同步紀錄應放在 `docs/99_整理與封存/`，並清楚標示其非現行效力。正式文件的新增、改名、移動或內容同步，應保留來源、修改時間、版本、變更原因與核准脈絡。

提交變更時建議使用 Conventional Commits，例如 `docs:`、`fix:`、`refactor:` 或 `chore:`。提交前至少執行 Markdown 引用檢查、版本與檔名檢查、`git diff --check`，並確認沒有把草稿或歷史文件誤列為現行 SSOT。
