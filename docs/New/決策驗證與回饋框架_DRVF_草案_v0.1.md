# 決策驗證與回饋框架（Decision Review & Validation Framework, DRVF）草案

> **文件狀態：** 草案・待CIO審閱（尚未正式生效，不具治理效力）
> **Version：** v0.1
> **提出脈絡：** 源自「試跑（Paper Trading）」討論延伸，經G大提出更完整之治理閉環設計，Claude彙整釐清三項與現行治理規範之銜接問題後產出本草案
> **定位：** 五大框架 → 決策層 → 行動層 之後新增的治理閉環節點，非第六大分析框架，不影響 AI基本面追蹤框架本身

---

## 一、核心定位

現行資料流（依《Constitution附錄・術語與命名規範》v1.0）：

```
框架分析 → 五大框架評分 → 框架檢核 → 決策層 → 行動層 → 官方儀表板
```

DRVF 於「行動層」之後新增一個回饋節點：

```
行動層（Action Layer）
   │
   ▼
審查層（Review Layer）— DRVF核心
   │
   ▼
知識回饋（Knowledge Feedback）
   （修正未來的判斷權重／治理規則，而非修正歷史紀錄）
```

**核心原則（建議列為硬性治理規定）：**

> **審查層不得修改當時的分析與判定，只能新增驗證紀錄。歷史決策紀錄永久保留原貌，事後驗證結果一律以新增條目呈現，不得回溯覆寫。**

此原則與《憲章附錄》資料流「上游結論是下游輸入，下游不得推翻上游判斷」精神一致，屬同一原則的時間軸延伸版本：不僅下游不得推翻上游，未來也不得推翻過去。

## 二、與現行規範的銜接（本次釐清重點）

### 2.1 信心等級欄位——避免與既有星等/Confidence混淆

現行已存在兩套相關但不同的標示：

| 既有欄位 | 定位 | 來源 |
|---|---|---|
| 證據等級（★☆☆☆☆～★★★★★） | 評估「資訊本身可不可信」 | Constitution v1.1.0 第8章 |
| Confidence（High／Medium／Low） | 每日固定輸出第3項，評估「當次判定的把握程度」 | Daily War Room SOP |

G大提出的 Calibration（信心校準）概念，評的是「決策信心與事後勝率是否相符」，性質上與既有 Confidence 高度重疊。

**建議：** 不新增第三套星等符號。DRVF 之信心欄位**直接沿用既有 Confidence（High／Medium／Low）**，事後統計「各信心等級對應的實際勝率」，驗證模型是否過度自信或過度保守。若三段式（High/Medium/Low）粒度不足以做有意義的統計分群，待累積樣本後再議是否需要更細的分級，不在草案階段預先擴充。

### 2.2 Decision Consistency——不引入數字評分，直接比對燈號組合

現行五大框架評分固定值為 🟢／🟡／🔴（或正向／中性／負向文字），Constitution 明確禁止數字化評分與「中性偏正向」等混合修飾詞。

**建議：** Decision Consistency 不採用數字分數（如92、88、80），而是直接比對「相同五大框架燈號組合」是否對應相同的 Action Layer 建議。例如：

> 兩次分析皆為「AI基本面🟢／估值🟡／市場情緒🟡／季節性🟡／技術面🔴」，若一次建議⏸️續抱、另一次建議⚠️減碼，即記錄為一次 Consistency 落差，附上兩次判定的分析說明差異作為後續檢討依據。

此設計完全沿用現行固定值，不需新增評分機制，也不牴觸「欄位不得混合分類」的既有紀律。

### 2.3 資料流節點——需同步更新《憲章附錄》

《憲章附錄》現行資料流圖標注「官方儀表板」為「最終呈現層，無下游」。DRVF 若正式收錄，需將附錄之資料流圖與名詞定義表一併修訂，新增「審查層」節點、其涵蓋範圍與輸出對象。**本草案階段不逕自修改附錄，待CIO確認方向後再依正式文件修訂流程處理。**

## 三、欄位定義（草案）

每一筆 Action Layer 建議，額外登錄以下欄位，作為 DRVF 追蹤紀錄：

| 欄位 | 說明 | 固定值來源 |
|---|---|---|
| 日期 | 建議產出日 | — |
| 標的 | 個股／ETF／家庭投資中心整體 | 依家庭投資中心六帳戶 |
| 建議 | 沿用行動層固定格式 | ✅建議加碼／⚠️建議減碼／⏸️續抱／👀觀望 |
| 判斷基礎 | 引用當次五大框架評分組合與主導因素 | 沿用五大框架固定值（🟢/🟡/🔴） |
| Confidence | 沿用既有欄位，不新增 | High／Medium／Low |
| 當時價位或淨值 | 用於後續報酬計算基準 | — |
| 1個月／3個月／6個月後續表現 | 事後回填，客觀數字 | — |
| 方向性判準 | 加碼／減碼建議事後是否驗證正確 | ✅／❌ |
| 時機性判準 | 分批區間是否貼近相對高低點 | ✅／❌／部分符合 |
| Decision Consistency | 相同燈號組合是否給出相同建議 | 一致／不一致（附差異說明） |
| 改善建議 | 若判斷有誤，記錄可能的修正方向 | 僅新增，不覆寫原判定 |

**強制規定：** 「改善建議」欄位僅描述未來如何調整判斷邏輯或框架權重，不得用於重寫或美化原始判定內容。原始「建議」「判斷基礎」欄位一經產出即永久鎖定。

## 四、正式化前置條件（依現行治理原則）

依《AI基本面追蹤框架》「分析方法成熟≠治理規則成熟」後設原則：

- 本草案定位為 **Working Practice**，尚不具治理效力。
- 建議先以既有 Daily War Room 產出的 Action Layer 建議為樣本，實際試跑並回填數個案例，驗證欄位設計是否好用、是否有遺漏。
- 累積 2–3 次不同情境（例如：一次修正期建議續抱、一次反彈期建議加碼、一次背離期建議觀望）驗證後，再評估是否依正式文件修訂流程（憲章附錄修訂＋Daily War Room SOP 新增章節）正式收錄。
- 若CIO決定個案特批直接收錄（比照 SOP v1.8 先例），亦可跳過驗證期，但須於版本紀錄中明確註記為特批處理，不構成常態豁免規則。

---

## 五、待CIO裁定事項

1. 是否採用「決策驗證與回饋框架（DRVF）」此名稱，或維持「試跑」等其他命名。
2. 是否同意本草案第二節之三項銜接方案（Confidence沿用既有欄位／Consistency不用數字分數／資料流圖待正式修訂再改）。
3. 正式化路徑：先走驗證期，或個案特批直接收錄。
4. 若同意先走驗證期，指定由哪一次／哪幾次 Daily War Room 的 Action Layer 建議作為首批試跑樣本。
