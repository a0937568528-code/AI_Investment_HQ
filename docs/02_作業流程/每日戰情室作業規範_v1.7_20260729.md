## 資訊分級（Information Tiering）

**定位：** 並非所有輸入資訊都需要走完整正式九欄判定流程。本節定義三種資訊類型與各自對應的處理規格，避免將輔助性、結論恆定的資訊（如純技術面短線解盤）過度套用正式治理格式，稀釋正式知識庫的訊號密度，也避免佔用不必要的分析資源。

| 資訊類型 | 判準（符合任一項即屬此類） | 是否套用九欄正式判定 | 用途 |
|---|---|---|---|
| **框架級情報**（Framework Intelligence） | ①來自公司財報、法說、官方公告、CapEx guidance等官方或準官方來源；②內容涉及 AI 基本面追蹤框架第一層或第二層指標（CSP CapEx、AI Workload、CoWoS/ABF利用率、HBM供需等）；③內容可能觸及框架失效條件 | 是 | 判定是否影響分析框架、決策層 |
| **背景事件**（Background Event） | ①內容與家庭投資中心持股（00991A／00981A／00988A／00997A／欣興／華邦電）有直接關聯，但非官方來源（如市場分析、KOL研究、第三方統計）；②來源具一定公信力（機構研究、主流財經媒體），內容涉及總經、估值、籌碼面等可能間接影響框架判讀之因素；③內容包含具體可驗證數字或事件，但尚待進一步查證來源等級 | 視情況（符合上列任一判準即建議套用九欄；若三項皆不符合，改列短線操作情報） | 作為支持性證據，保留歷史紀錄供交叉驗證 |
| **短線操作情報**（Trading Notes） | 純技術分析、市場評論、影音解盤等，內容為支撐壓力位、進出場條件、籌碼觀察，且結論恆定為「與分析框架不衝突」（技術面本為五大框架最末位輔助項，依框架設計不會、也不應觸發框架層級變動） | 否 | 僅供短線加減碼節奏參考，不進入正式治理流程 |

**短線操作情報固定簡式格式：**

```
[日期]｜[來源]

大盤／個股：[支撐壓力位、觸發條件]

[持股名稱，如有提及]：[停損/加碼條件]

備註：僅供短線操作節奏參考，不構成分析框架判定。
```

**與其他文件之關係：** 本分級僅決定「是否套用九欄格式」，不改變 Constitution v1.1.0 第 8 章對九欄格式本身的定義；框架級情報與需套用九欄之背景事件，仍須完全依第 8 章規範輸出。

**混合來源情報處理原則：** 資訊分級之判定單位為「證據」而非「文章」。當單一情報同時包含官方可獨立查證之事實（如財報數字、法說內容、CapEx guidance 等）與第三方分析、估值解讀或市場推論時，不得因文章整體混合了不同來源，而將全篇情報整體升級或整體降級為單一分級。應拆分處理：

- 涉及分析框架第一層或第二層之官方事實部分，獨立適用**框架級情報**判準，套用完整九欄正式判定。
- 其餘第三方分析、推論、市場解讀部分，依內容性質判定為**背景事件**或**短線操作情報**，各自適用對應規格。

同一份情報因此可能同時產出多個資訊等級的紀錄，不強制單一文章對應單一等級。此原則適用於 GE、G大、Claude 三方對混合型情報之判定，確保跨角色分級結果一致。

**同級內部證據等級不一致之拆分規則：** 即使同一情報之各子項均已判定為相同資訊分級（如均屬框架級情報），若各子項證據等級不同（例如同一事件同時包含官方法說之具體數字，與該法說並未提及、僅為券商或媒體額外推估之項目），仍須拆分為獨立九欄各自判定，不得合併為單一九欄。

理由：若合併判定，因「分析框架」欄位僅有「已獲確認」與「與分析框架不衝突」二值，較低證據等級之子項將拖累整筆判定降級，導致原本可獨立成立之官方事實喪失其應有之「已獲確認」效力。

範例：某公司法說官方揭露 CapEx guidance 上修（可獨立判定「已獲確認」），但同一則情報另外提及第三方對其下游客戶技術路線之推測（僅為券商預估，非法說內容），此推測部分須拆出獨立九欄判定為「與分析框架不衝突」，不得與前者合併，否則官方 CapEx guidance 之判定將被錯誤降級。

## 正式輸出前自我檢核（Pre-Output Self-QA）

**定位：** 所有正式九欄判定輸出（不限於結案摘要，包含每一次分析回應）於送交使用者或 Claude 稽核前，須先完成本檢核清單並直接修正發現之問題，不得將「發現問題但未修正」視為已完成 QA。

**核心原則：** Self-QA 的目的是修正完成，不是找出問題後留待他人（使用者或 Claude）修正。流程須為「完成分析 → Self-QA → 直接修正 → 再次確認 → 正式輸出」，不得停留在「完成分析 → Self-QA → 發現問題 → 提醒使用者」。

**檢核清單：**

- □ 九欄是否完整（資訊來源／證據等級／證據類型／影響程度／分析框架／分析框架狀態／失效條件／家庭投資中心／Claude 深度研究）
- □ 九欄固定值是否全部符合 Constitution v1.1.0 第 8 章定義
- □ 證據等級是否使用 ★☆☆☆☆～★★★★★ 固定星等格式，不得使用「高／中／低」等未定義表示方式
- □ 「分析框架」與「分析框架狀態」是否混用或誤植（前者固定值為「與分析框架不衝突／分析框架已獲確認」，後者固定值為「維持不變／更新」，兩者為不同維度，不得互相替代）
- □ 是否出現未定義固定值或自創混合分類
- □ 是否出現「偏正向」「偏中性」「偏觀察」等含「偏」字之違禁修飾詞
- □ 家庭投資中心六帳戶（00991A／00981A／00988A／00997A／欣興／華邦電）是否完整引用
- □ 若持股資料非最新版，是否明確標示「未評估」及原因，而非以模糊詞帶過仍給出方向性判定
- □ 官方中文術語是否符合 Constitution（無英文欄位名稱或治理用語，如 Decision Layer 應譯為決策層）
- □ 「分析框架」欄位是否僅使用固定值（與分析框架不衝突／分析框架已獲確認），不得誤填「第一層／第二層／第三層」等層級歸屬；層級歸屬僅得出現於分析說明文字，不得進入固定欄位
- □ 「失效條件」欄位是否僅使用固定值（未觸發／已觸發），不得附加層級（如「未觸發第一層失效條件」）或使用「尚未判定」等非固定值表述
- □ 若判定涉及第三層（驗證端），是否僅限 AI 基本面追蹤框架定義之驗證性指標（Hyperscaler AI Revenue、AI ROI、持股實際財務表現）；不得將籌碼進出、法人買賣超、技術面、市場情緒等背景事件內容誤列為第三層驗證，此類內容應維持為背景事件並於分析說明中明確排除其屬於第三層之可能

**輸出品質建議（非 Constitution 強制格式，但列為正式輸出慣例）：** 家庭投資中心六帳戶逐項判定時，建議每一帳戶皆附簡短理由（例如「00988A ⚪中性（事件未改變投資假設）」），而非僅列出符號，以提升可稽核性。

## Action Layer（操作層）

**定位：** Action Layer 屬於 Daily War Room 的輸出項目，負責將 Framework／Decision Layer 的結論轉換為操作建議，**不得單獨推翻或與 Framework 相反**。

**固定格式：**
✅建議加碼（理由+分批區間）／⚠️建議減碼（理由+分批區間）／⏸️續抱（理由+後續觀察重點）／👀觀望（等待哪些條件成立）

無明確建議時仍須寫出「目前沒有建議加碼，維持續抱／觀望」。

**若未引用最新版家庭投資中心（SSOT）：** 不得直接省略 Action Layer，應明確標示「未引用最新版家庭投資中心（SSOT），不提供正式操作建議」。

**對應規則：**
- 🟢Framework看多但技術面短線轉弱 → Action Layer為「續抱」或「等待拉回分批加碼」，不可直接建議減碼
- 🟡Framework中性 → Action Layer可給「觀望」或「分批布局」
- 🔴Framework看空 → Action Layer才可建議減碼或停止加碼

適用範圍：晨報、收盤分析、War Room、重大事件、個股與ETF評估，不須等使用者詢問即主動提出。

## 結案摘要（Closing Summary）

**定位：** 每一次每日戰情室、重大事件分析、Event Update 完成正式判定並經使用者確認結案後，須固定產出一段可直接留存、複製或轉發的結案摘要，作為該次分析的正式紀錄封裝。

**觸發時機：** 使用者明確表示「結案」「本案結案」或等同語意時，緊接著輸出結案摘要；不需使用者另外要求「幫我寫摘要」才產出。

**固定格式：**

```
AI Investment HQ｜[每日戰情室／重大事件分析] 結案摘要

事件：[事件標題]

| 項目 | 判定 |
|---|---|
| 事件定位 | 背景事件／Framework Update |
| 資訊來源 | ... |
| 證據等級 | ★☆☆☆☆～★★★★★ |
| 證據類型 | 事實／推論／待驗證（僅限三選一，依 Constitution v1.1.0 第 8 章；若同一事件同時涉及事實與推論內容，應於內文分段落分別標示【事實】【推論】，不得於本欄位混合填寫） |
| 影響程度 | 🟢正向／⚪中性／🔴負向 |
| 分析框架 | 與分析框架不衝突／分析框架已獲確認 |
| 分析框架狀態 | 維持不變／更新 |
| 失效條件 | 未觸發／已觸發 |
| 家庭投資中心 | 未評估／[具體影響判定] |
| Claude 深度研究 | 啟動／不啟動 |

結論：[兩到三句話，說明本次事件對分析框架的意義、與既有框架的關係、後續關鍵驗證點]

本案正式結案。
```

**格式一致性要求：** 結案摘要之欄位名稱、證據類型與影響程度之固定值，一律依 Constitution v1.1.0 第 8 章「官方中文術語規範」執行，不得使用英文欄位名稱、不得自創欄位值（如「分析架構」「中性偏正向」等）。

**與 Action Layer 的關係：** 結案摘要為判定結果之封裝呈現，不重複展開 Action Layer 之完整理由；若該次分析已於前段給出 Action Layer，結案摘要之「家庭投資中心」欄位可簡述其判定（如「⏸️續抱，理由見上」），不需重寫全文。

- v1.3（2026-07-26）：新增「資訊分級（Information Tiering）」章節，定義框架級情報／背景事件／短線操作情報三類資訊之判準與對應處理規格，解決「哪些資訊可豁免九欄正式判定」之治理缺口（原正式文件僅定義九欄格式本身與技術面屬五大框架輔助項，未定義豁免條件）。此為治理缺口補正，非執行疏漏修正。
- v1.4（2026-07-26）：於「資訊分級」章節新增「混合來源情報處理原則」，明定資訊分級之判定單位為「證據」而非「文章」；單一情報同時包含官方事實與第三方分析時，應拆分處理，官方事實部分獨立適用框架級情報判準，不得因文章整體混合來源而全篇升級或降級。此為治理缺口補正——原 SOP v1.3 僅定義三類資訊之判準，未回答「判定單位是文章還是證據」，導致 GE／GPT／Claude 對混合型情報可能做出不一致判定。
- v1.5（2026-07-27）：新增「同級內部證據等級不一致之拆分規則」，明定即使同一情報之子項均屬相同資訊分級，若各子項證據等級不同（如官方法說數字 vs. 券商額外推估），仍須拆分為獨立九欄，不得合併，以避免官方事實被較低證據等級之子項拖累降級為「與分析框架不衝突」。此為治理缺口補正——源自實際案例（TSMC 2Q26 法說 vs. Google TPU 券商預估被原始情報混為一談），發現原 SOP 混合來源原則僅處理「跨資訊分級」之拆分，未明確處理「同一分級內部證據等級不一」之情況。
- v1.6（2026-07-27）：新增「正式輸出前自我檢核（Pre-Output Self-QA）」章節，訂定九項檢核清單（含九欄完整性、固定值格式、分析框架與分析框架狀態不得混用、違禁修飾詞、六帳戶完整性、未評估標示、中文化術語等），並明定 Self-QA 之目的為「修正完成再輸出」而非「發現問題後提醒使用者」。此源自實際案例（G大於同一次輸出中同時出現證據等級格式錯誤、分析框架與分析框架狀態誤植兩處問題），經確認相關規則雖已散見於 Constitution 第 8 章與 SOP 各節，但缺乏一份輸出前之整合檢核清單，屬治理缺口補正。
- v1.7（2026-07-27）：於 Pre-Output Self-QA 檢核清單新增三項：①「分析框架」欄位不得誤填第一／二／三層層級（層級歸屬僅得置於分析說明文字）；②「失效條件」欄位不得附加層級或使用「尚未判定」等非固定值；③第三層（驗證端）僅限 AI Revenue／AI ROI／持股財務驗證等驗證性指標，不得將籌碼、法人買賣超、技術面、市場情緒誤列為第三層。此源自實際案例（G大將國發會景氣燈號、宇瞻法說、華邦電籌碼、超級財報週四則事件之「分析框架」欄位誤填層級，並將華邦電外資賣超誤歸類為第三層驗證），屬既有規則（Constitution 第 8 章固定值、AI基本面追蹤框架第三層定義）之執行疏漏，非治理缺口，惟因層級誤填屬反覆出現之錯誤模式，依稽核判準納入正式檢核清單以強化執行機制。
