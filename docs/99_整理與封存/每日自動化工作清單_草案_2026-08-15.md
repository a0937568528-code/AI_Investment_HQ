# AI 投資總部｜每日自動化工作清單（草案）

**文件日期：** 2026-08-15  
**文件狀態：** 工作清單草案，尚未啟用為正式排程  
**適用基線：** AI 投資總部憲章 v1.8.0、知識索引 v1.3、每日戰情室作業規範 v2.3、AI 基本面追蹤框架 v1.3、MA21／81＋100／80／80／0 正式風控規格書 v1.3、風控官正式指令工作 v1.1、晨晚報視覺化儀表板格式規格 v1.1  
**整理原則：** 本文件把既有規則轉成可執行的工作清單，不新增投資規則、風控參數或正式治理權限；若要成為正式作業文件，仍須經 CIO 核准並回寫至對應正式文件。

## 一、先講結論

完整的每日工作不是「每天自動搜尋新聞並直接下結論」。目前正式文件規定的是一條**CIO 提供原始情報、系統持續整理、收盤後獨立執行風控、晚間完成正式情報統合、最後封裝儀表板與歸檔**的工作鏈。

其中只有部分工作適合固定自動執行。每日情報的來源仍以 CIO 放入「今日工作區」的內容為起點；正式分析不能在沒有資料的情況下自行假設當日事件。風控判定則是收盤後的獨立平行流程，戰情室只引用風控官當日結果，不自行重算或改寫風控模型。[1][2]

> **目前狀態：** 本工作階段尚未啟用任何新的每日排程；以下是依正式文件建立的「應有工作清單」與「自動化藍圖」，不是已經啟用的排程表。

## 二、每日任務分層

| 分層 | 定義 | 目前是否應自動化 | 是否需要 CIO 介入 |
|---|---|---|---|
| 固定每日流程 | 每個工作日或每個交易日都應執行的固定工作 | 是，適合固定觸發 | 部分需要，尤其是原始情報與最終裁定 |
| 事件觸發流程 | CIO 放入新聞、截圖、法說、財報或其他資料後才啟動 | 是，適合新輸入觸發 | 需要 CIO 提供資料；系統不得自行補造事件 |
| 收盤後風控流程 | 台股正式收盤資料可取得後，依正式風控規格判定 | 是，適合交易日收盤後觸發 | 不需要逐次人工計算，但正式異常或規則問題須回報 CIO |
| 條件式深度研究 | 分析閘門判定需要反證、交叉驗證或壓力測試後才啟動 | 不應每日固定執行 | 需要 CIO 核准後才執行 |
| 條件式結案與治理同步 | 使用者明確結案，或正式規則／框架／風控模型發生異動後觸發 | 事件觸發 | 必須通知 CIO；正式生效仍由 CIO 裁定 |
| 非每日工作 | 季度檢視、年度框架 Review、一次性架構搬遷與文件整理 | 不應每日執行 | 依治理程序另行處理 |

## 三、每日總時序

下表是建議的每日自動化時序。文件沒有授權自行發明精確時鐘的工作，故凡涉及市場資料的流程，採用「資料條件成立後」而不是硬編一個可能錯誤的時間。

| 時段／觸發點 | 工作鏈 | 主要產物 | 自動化等級 |
|---|---|---|---|
| 每日開始或首次執行前 | 載入知識索引、憲章、SOP、基本面框架；若涉及風險則載入風控規格；載入最新家庭投資中心 | 當日工作基線 | 固定自動 |
| 全天、每次收到新資料 | 今日工作區接收、來源與時間標記、去重、事件索引、合併多來源、事實／推論／市場情緒區分 | 背景情報索引，不產生正式投資結論 | 事件觸發自動；資料由 CIO 提供 |
| 台股正式收盤資料可取得後，每個交易日 | 風控官執行資料驗證、MA21／MA81 計算、四狀態判定、極端波動附則檢查 | 當日風控官正式判定與隔日執行水位 | 收盤後自動 |
| 風控結果產出後 | 將風控結果標記為可供晚間戰情室引用的正式輸入；若資料不足則標示不可引用 | 風控引用卡 | 自動 |
| 晚間 20:00–21:00 | 完成每日情報統合、Temporal QA、資訊分級、九欄判定、五大框架評分、決策層與行動層 | Official Daily War Room 草案／正式輸出草案 | 固定自動，但受今日資料量影響 |
| 晚間正式分析完成後 | 執行 Self-QA，檢查九欄、固定值、所有家庭帳戶／持股、風控引用與官方中文術語 | QA 通過的正式文字輸出 | 自動 |
| 正式文字輸出後 | 以正式結果封裝晨／晚報儀表板；儀表板不得自行產生新判定 | 儀表板呈現層 | 自動 |
| 正式研究或規則異動發生後 | 將正式資料歸檔、草稿放入 New 區，若涉及規則異動則產生 CIO 人工同步提醒 | Drive 歸檔與同步提醒 | 事件觸發自動 |
| CIO 明確表示結案後 | 產出固定格式結案摘要 | Closing Summary | 事件觸發自動 |

## 四、A 線：每日開始前的基線載入

這不是投資判定，而是每次正式工作前的固定防錯程序。系統應先載入知識索引，再依索引順序讀取憲章、每日戰情室規範、AI 基本面追蹤框架；若分析涉及持股水位或風險，追加讀取正式風控規格書與風控官執行介面；最後讀取最新家庭投資中心。[2]

### 執行清單

- [ ] 讀取 `AI投資總部知識索引`，確認當日引用順序。
- [ ] 讀取 `AI投資總部憲章`，確認官方術語、文件優先順序、家庭投資中心完整引用規則與決策邊界。
- [ ] 讀取 `每日戰情室作業規範`，確認資訊分級、九欄、Self-QA、行動層與風控引用規則。
- [ ] 讀取 `AI基本面追蹤框架`，確認第一層、第二層、第三層指標與失效條件。
- [ ] 若涉及持股水位或風險，讀取 `MA21-81_100-80-80-0_正式規格書` 與 `風控官正式指令工作`。
- [ ] 讀取最新版 `家庭投資中心`；不得使用聊天記憶或前一日持股資料代替。
- [ ] 記錄當日工作日期、資料截止時間與所使用的文件版本。
- [ ] 若任何必要文件缺失或版本不明，標示「待確認」，不得直接產出 Official 結論。

## 五、B 線：全天今日工作區與事件觸發整理

現行 CIO 直送模式要求 CIO 全天將有價值資訊貼入今日工作區，不要求 CIO 預先分類或即時分析。系統在收到每筆資料後，只做背景整理，不直接形成正式投資結論。[1]

### 每筆新輸入的自動化處理

- [ ] 記錄收到時間與原始來源。
- [ ] 保留原文、截圖或附件原貌；不得把原始資訊改寫成未標示的推論。
- [ ] 判斷是否與既有事件重複。
- [ ] 建立或更新事件索引，合併同一事件的多來源內容。
- [ ] 分開標記事實、推論與市場情緒。
- [ ] 標記涉及的公司、產業節點、家庭投資中心持股與可能影響層級。
- [ ] 對混合來源內容拆成可獨立判定的證據單位，不以整篇文章作單一分級。
- [ ] 對同一資訊分級但證據等級不同的子項分開保存，不把官方事實與第三方推估合併。
- [ ] 將內容暫分為框架級情報、背景事件或短線操作情報。
- [ ] 僅建立待晚間正式分析使用的背景資料，不提前宣告「分析框架已獲確認」或改變長期投資假設。

### 事件觸發條件

若新輸入涉及法說、財報、官方公告、CapEx guidance、AI Workload、CoWoS／ABF／HBM、持股財務表現或可能觸及框架失效條件，應標記為高優先級框架級情報候選；若只是第三方市場評論、技術面或影音解盤，應按背景事件或短線操作情報處理，不得自動升級為正式框架更新。[1][5]

## 六、C 線：收盤後風控官流程（每個交易日）

風控官流程與每日戰情室是兩條平行流程。風控官只使用台股加權指數的正式收盤資料與完整歷史收盤資料，不使用盤中價格、期貨或其他指數。當日判定於收盤後完成，正式水位於下一個交易日開盤後生效。[3][4]

### C1. 資料取得與驗證

- [ ] 確認最新交易日與資料日期正確。
- [ ] 確認使用正式收盤資料，不使用盤中值。
- [ ] 確認至少有完整 21 個有效交易日以計算 MA21。
- [ ] 確認至少有完整 81 個有效交易日以計算 MA81。
- [ ] 檢查缺漏、重複、日期錯置與異常值。
- [ ] 確認 MA21、MA81 都以收盤價算術平均計算。
- [ ] 若資料不足或異常，輸出「資料不足，暫不判定」，不得猜測持股水位。

### C2. 四狀態判定

| 判定條件 | 正式狀態 | 正式持股水位 |
|---|---|---:|
| 收盤價 ≥ MA21，且 MA21 ≥ MA81 | 多頭完整 | 100% |
| 收盤價 < MA21，且 MA21 ≥ MA81 | 多頭修正 | 80% |
| 收盤價 ≥ MA21，且 MA21 < MA81 | 空頭反彈 | 80% |
| 收盤價 < MA21，且 MA21 < MA81 | 正式空頭 | 0% |

系統必須保存收盤價、MA21、MA81、兩組比較結果、四狀態與正式持股水位，讓判定可由三個輸入值完全重現。模型是每日獨立判定，不依賴前一日狀態記憶，也不得混入舊 MA20／60、S2、V1.0.5、V2、A 或 C 模型。[3]

### C3. 極端波動部位管理附則

只有在當日正式狀態為「正式空頭」且正式水位為 0% 時，才檢查極端波動附則；狀態一、二、三不得建立機動試單。[3][4]

- [ ] 定義 Day 0 為退至 0% 的收盤判定日，不是隔日 0% 生效日。
- [ ] 檢查 Day 0 收盤價相對於含 Day 0 在內、往前 21 個交易日最高價是否跌幅超過 15%。
- [ ] 未超過 15%：標示未觸發，不另建立試單流程。
- [ ] 超過 15%：建立極端急跌事件，Day 1、Day 2 為有效時間鎖，Day 3 起永久失去本次試單資格。
- [ ] Day 1–Day 2 若當日收盤突破前一交易日最高價，下一交易日開盤建立固定 20% 機動曝險。
- [ ] 20% 試單若收盤跌破觸發試單當日 K 線低點，下一交易日開盤由 20% 回到 0%。
- [ ] 正式 B 模型重新判定 80% 或 100% 時，立即標示已交回主體，後續只依正式 B 模型執行。
- [ ] 輸出極端波動附則狀態：未觸發／觀察中（Day1–2）／20%試單中／已停損／已交回主體。

### C4. 風控官固定輸出

每次風控判定固定輸出資料日期、加權指數收盤、MA21、MA81、收盤與 MA21 關係、MA21 與 MA81 關係、風控狀態、正式持股水位、極端波動附則狀態、一句判定理由與「下一交易日執行 XX% 持股」。若資料不足，改輸出暫不判定，不得沿用前一日結果。[4]

## 七、D 線：晚間每日情報統合與正式戰情室

每日情報統合的固定時段為 20:00–21:00。它不是逐則複述新聞，而是將全天資訊轉成可支援決策的框架級情報，並回答市場真正交易的內容、框架級事件、背景事件／噪音、認知更新、家庭投資中心影響與是否需要深度研究六個問題。[1]

### D1. 正式流程順序

- [ ] **Temporal QA（時空核對）**：確認當前年月日、現任主體與財報期別。
- [ ] 判定每個證據單位的資訊分級。
- [ ] 若 CIO 當日提供美股收盤截圖或美股資訊，納入背景摘要；若沒有提供，不能自行假造晨報資料。舊有自動化四大面向與昨夜美股摘要只在重新啟用自動蒐集模式時適用。
- [ ] 對框架級情報與需要正式判定的背景事件建立九欄。
- [ ] 完成 AI 基本面三層框架判定，分清第一層領先、第二層確認、第三層驗證。
- [ ] 完成五大框架評分：AI 基本面、估值、市場情緒、季節性、技術面，並指出主導因素。
- [ ] 給出 Confidence：High／Medium／Low 與理由。
- [ ] 列出今日未揭露的重要資訊。
- [ ] 列出支持與反證，並使用證據等級、證據類型、影響程度的正式格式。
- [ ] 判定是否需要 Event Update，以及屬於 Framework Update 或背景事件。
- [ ] 判定是否需要更新 Framework 正式文件。
- [ ] 判定是否改變長期投資假設，並附支持性證據。
- [ ] 若正式分析涉及持股水位或投資組合風險，引用 C 線風控官當日正式判定；若沒有結果，明確寫「風控判定未提供，本次分析不含風控水位資訊」。
- [ ] 完成 Decision Layer 與 Action Layer；Action Layer 不得推翻分析框架，固定使用建議加碼／建議減碼／續抱／觀望四類表達。
- [ ] 完整列出家庭投資中心所有已登錄帳戶與持股，不得只列出當日新聞提及標的。現有資料中至少應覆蓋 00981A、00988A、00991A、00997A、3037 欣興與 2344 華邦電，並按帳戶逐項說明影響或標示未評估。[1][5]

### D2. 九欄 Self-QA

正式輸出前，系統必須先自我修正，再交付 CIO，不得只報告發現問題而不修正。

- [ ] 資訊來源完整。
- [ ] 證據等級使用 ★☆☆☆☆ 至 ★★★★★。
- [ ] 證據類型僅使用事實／推論／待驗證。
- [ ] 影響程度僅使用正向／中性／負向固定值。
- [ ] 分析框架欄位僅使用「與分析框架不衝突／分析框架已獲確認」。
- [ ] 分析框架狀態僅使用「維持不變／更新」。
- [ ] 失效條件僅使用「未觸發／已觸發」。
- [ ] 家庭投資中心欄位完整，若未引用最新資料則標示未評估。
- [ ] Manus 深度研究欄位標示啟動／不啟動，並與實際核准狀態一致。
- [ ] 不使用「偏正向」「中性偏正向」等自創混合值。
- [ ] 不把第一層／第二層／第三層直接填入分析框架固定欄位。
- [ ] 不把籌碼、法人買賣超、技術面或市場情緒誤列為第三層驗證。
- [ ] 若涉及風控，已引用當日風控官正式結果，沒有自行重算或改寫模型。
- [ ] 所有正式用語符合憲章的官方中文術語規範。

## 八、E 線：每日儀表板封裝

儀表板是正式輸出的下游呈現層，不得獨立產生判定。它只能使用已完成 Self-QA 的文字結果、風控官結果與家庭投資中心影響判定。[6]

### 固定標題列

- [ ] 左上：`AI Investment HQ｜每日戰情室（晨報／晚報）`。
- [ ] 中央：西元日期、星期與晨／晚圖示。
- [ ] 右上：`基本面為本・風控為先・紀律執行・長期致勝`。

### 六大板塊

| 板塊 | 必須呈現 |
|---|---|
| ① 市場背景摘要 | 晚報使用今日台股收盤；晨報只有在具備美股資料時使用昨夜美股摘要 |
| ② 決策層 | AI 基本面三層框架、當日財報／法說重點與框架維持／更新 |
| ③ 正式風控判定 | 四狀態、正式水位、收盤 vs MA21、MA21 vs MA81、極端波動附則狀態與規格一致性 |
| ④ 今日重點事件 | 台股向重點事件與簡短說明 |
| ⑤ 家庭投資中心影響 | 00991A、00988A、00997A、00981A、3037 欣興、2344 華邦電之代號／名稱、今日表現與支持性證據 |
| ⑥ 關鍵指數與技術位階 | 加權指數收盤、MA21／MA81、近期走勢與技術摘要 |

底部固定區塊為「後續觀察重點」與「今日核心結論」。若儀表板與九欄／文字版判定不一致，以正式九欄／文字版為準，儀表板不得覆蓋上游結論。[6]

## 九、F 線：研究、歸檔與治理收尾

### F1. 深度研究不是每日固定任務

只有當分析閘門判定需要反證、交叉驗證、長篇研究或壓力測試時，才提出深度研究需求；CIO 核准後才執行。深度研究完成後，分析閘門整合研究證據，CIO 再作正式治理裁定。不得把每日每一則新聞都自動送進深度研究，以免造成不必要的成本與流程負擔。[7]

### F2. 文件歸檔

- [ ] CIO 明確要求保留、框架級情報、觸發失效條件、正式文件修訂或研究結案等正式性資料，直接歸檔至適當 Drive 正式資料夾。
- [ ] 尚未經 CIO 確認的一般草稿，先存入 `New` 子資料夾，不得直接放入正式資料夾。
- [ ] 歸檔時回報檔案位置與分類理由。
- [ ] 不得讓正式研究只留在聊天紀錄中。

### F3. 規則異動通知

若正式治理規則、分析框架、風控模型或正式輸出格式發生新增、修訂或升版，完成歸檔後必須產生 CIO 同步提醒，具體寫明哪一份文件、哪個章節、改了什麼，以及需要手動同步到哪些獨立執行端。僅涉及本端工作方式且不影響其他判定邏輯的變更，才不觸發跨端同步提醒。[1]

## 十、G 線：結案摘要

結案摘要不是每天無條件產出。只有 CIO 明確表示「結案」「本案結案」或同等語意時，才輸出固定格式的結案摘要；摘要應封裝事件定位、來源、證據等級、證據類型、影響程度、分析框架、框架狀態、失效條件、家庭投資中心、深度研究狀態與兩至三句結論。[1]

## 十二、不應排入每日固定排程的工作

以下工作雖然屬於 AI 投資總部的重要工作，但不應每天固定執行：

| 工作 | 正確頻率或觸發方式 |
|---|---|
| Manus 深度研究、反證與壓力測試 | 分析閘門提出需求且 CIO 核准後 |
| AI 供應鏈關聯公司清單檢視 | 原則上每季，重大結構變化時提前 |
| AI 基本面框架定義與資料來源 Review | 原則上每年，或正式治理程序觸發 |
| 架構搬遷、Diff 報告、文件同步 | 一次性建置／治理任務 |
| Google Workspace 連接器測試與示範 | 一次性測試或功能驗證 |
| 風控模型回測、壓力測試與交易成本驗證 | 研究或治理任務，不是每日風控判定 |
| 結案摘要 | CIO 明確表示結案時 |
| 晨報自動新聞蒐集 | 現行 CIO 直送模式不啟用；除非 CIO 另行核准恢復自動蒐集模式 |

## 十三、實際啟用方式的兩個候選方案

目前沒有啟用任何新排程。若要把本清單落地，可在 CIO 確認後從下列兩種方式選擇；本表只比較方案，不替 CIO 預先決定。

| 方案 | 做法 | 優點 | 代價與限制 |
|---|---|---|---|
| A：輕量每日執行 | 以固定的每日晚間任務執行基線載入、風控引用檢查、晚間統合與儀表板封裝；白天由 CIO 將情報放入今日工作區 | 設定快、維持現有 Manus 工作模式、無需另建管理介面 | 每次執行都會啟動完整分析流程；白天情報仍依賴 CIO 主動提供；風控若要獨立自動化需另設流程 |
| B：分離式自動化 | 用程式化流程處理收盤資料、MA21／MA81、資料驗證與固定格式輸出；只在需要語意判斷、研究或晚間統合時交由 AI 執行 | 風控與資料檢查可重複、成本與延遲較容易控制，適合長期擴充 | 建置與維護較複雜，需要持續運行環境、資料來源與錯誤監控；仍不能取代 CIO 最終裁定 |
