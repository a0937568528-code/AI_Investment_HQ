# Risk First Model 水位燈號呈現規則（Output Layer Pilot）

**版本：** Pilot v0.1（試行中，非正式規格）
**日期：** 2026/08/05
**狀態：** Output Layer Pilot（純呈現層試行，不影響State機、水位邏輯、缺口判定、均線確認、Decision Layer本體）
**適用範圍：** 晨報／晚報之 Risk First Model 風控判定區塊呈現方式

---

## 一、目的

本規則僅調整水位判定結果的「呈現方式」，不改變任何判斷邏輯、觸發條件或計算結果。風控官仍須依《風險優先模型_v1.0_正式規格書》第7～11節完整執行每日判定（新缺口、均線確認、水位判定、追蹤缺口揭露），本規則只規範**判定完成後**如何呈現給使用者。

---

## 二、燈號對照表

| 燈號 | 對應水位 | 涵蓋State |
|---|---|---|
| 🟢 綠燈 | 100% | State 0（滿倉） |
| 🟡 黃燈 | 80% | State 1 |
| 🔴 紅燈 | 60% | State 2 |
| 🔴 紅燈 | 50% | State 3 |

**注意：** 60%與50%皆用紅燈，不再用不同顏色區分；實際持股百分比數字仍須完整標示（例如「🔴 60%」與「🔴 50%」不可只寫「🔴」）。

---

## 三、快出標記規則

**僅在以下唯一情境**加註「⚠️快出」：

> 由 **100% → 80%**（第一次減碼，觸發條件：第一個反向／空方缺口）

格式範例：
⚠️ 快出
🟡 80%
**其餘所有水位變動**（第二次減碼、第三次減碼、任何回補）**一律不加註「加碼／減碼」文字**，直接呈現目前水位即可：
🔴 60%
---

## 四、呈現範例對照

**舊呈現方式（不再使用）：**
> 水位階段：State 2
> 建議總持股比例：60%（第二次減碼）
> 今日操作：維持不變

**新呈現方式（Pilot）：**
> 目前水位：
> 🔴 60%

**發生第一次減碼當天：**
> ⚠️ 快出
> 🟡 80%
> （觸發：第一個反向缺口）

---

## 五、不變的部分（提醒）

以下判定內容與流程**完全不受本規則影響**，風控官每日仍須完整輸出：

- 新缺口判定（第4、8節定義）
- 均線確認判定
- 追蹤中缺口揭露（第11節第6步）
- 觸發事件名稱（第一次／第二次／第三次減碼或回補，依規格書第9、10節表格對應）
- State數字與百分比的完整揭露

**本燈號規則只是包裝呈現的最後一步，不能取代上述完整判定過程的輸出。**

---

## 六、治理狀態

本規則為 **Output Layer Pilot**，非正式規格。待Risk First Model連續穩定運作一段時間後，CIO將評估是否正式收錄為《風險優先模型規格書》v1.1新增「Output Standard」一節。在正式收錄前，本文件僅供試行參考，如與《風險優先模型_v1.0_正式規格書》內容有任何衝突，一律以正式規格書為準（本文件不涉及、也不得涉及任何判斷邏輯變更）。

## 七、命名一致性提醒（避免回補階段誤標）

依規格書第10節，回補階段名稱**固定對應水位變化區間**，不是「本輪第幾次觸發」：

| 階段名稱 | 水位變化 |
|---|---|
| 第一次回補 | 50% → 60% |
| 第二次回補 | 60% → 80% |
| 第三次回補 | 80% → 100% |

**判定時請直接依「今日水位變化區間」查表對應階段名稱，不要用「這是本輪第幾次回補事件」自行計數**，兩者容易混淆但定義不同。

正式判定文字格式統一為：
> 原水位：__%（State __）
> 觸發事件：__（均線__確認 / 第__個同向缺口）
> 第__次回補：__% → __%（State __ → State __）

事件名稱＋水位變化＋State對照三者需一起寫，與CSV欄位保持一致。
