## 一、起點：左側交易／右側交易之討論

對話始於使用者分享一篇關於「左側交易與右側交易」之市場評論文章，Claude 分析其與 AI Investment HQ 既有 Framework First → Decision Layer → Action Layer 架構之對應關係，並指出文章中「三段式建倉（4-3-3）」「右側確認訊號（站回20MA、突破近5-10日高點、量能放大）」「ETF 作為左側佈局工具」等具體操作工具，可作為 Action Layer 分批區間之參考，但尚未正式驗證，先列為 Working Practice。

## 二、缺口診斷：部位管理與風險預算

使用者提出 AI Investment HQ 已有完整基本面、治理、決策流程，但缺少「部位管理框架」與「風險預算框架」兩份正式文件，並以「基本面決定方向，估值決定成本，右側決定部位，風險管理決定能走多遠」總結四環節之完整度落差。

經多輪討論收斂：

- 部位管理不應是第六個分析框架，而應是 Decision Layer → Action Layer 之間的「量化映射層」，不重新判斷市場。
- 真正缺少的是「決策→部位」這一步的映射規則（Mapping Rule），而非新框架。
- 風險預算屬於投資政策（Investment Policy），須由 CIO 專屬裁量，不能由 AI 推導出具體數字，以避免 False Precision。

## 三、文件歸屬定位：投資政策的位置

討論投資政策應歸屬何處：

- 一度考慮新增獨立「投資政策」頂層分類，後裁定**不新增頂層分類**，改歸屬《家庭投資中心》體系之下，理由是分析框架具普遍性（適用所有投資組合），投資政策具個別性（因投資組合的風險屬性而異）。
- 進一步裁定：《風險管理政策》採**獨立子文件**形式，不併入《家庭投資中心》主文件，理由是政策與資料更新頻率與觸發原因不同，混寫會造成治理上的干擾。
- 部位配置對照表定位為《風險管理政策》之**附錄**，而非獨立文件，避免同一數值分散於多處造成版本不同步。

## 四、《風險管理政策》草擬過程

依序完成四章與三個附件：

**第一章（政策定位）：** 制定目的、文件定位（僅定義風險承擔方式，不定義市場判斷）、適用範圍、與治理架構之關係、治理原則、適用原則（CIO 個案裁定重大情況）。

**第二章（風險承受原則）：** 建立「警戒」與「防禦」二級風險分級機制，警戒門檻從寬（單一訊號即觸發）、防禦門檻從嚴（須多項訊號共同確認）。透過多輪問答確立：

- 防禦性減碼不改變分析框架與決策層判定，屬臨時性風險管理措施。
- 此機制構成《每日戰情室作業規範》現行規則之例外情境（提案性質，尚待正式修訂）。

**第三章（整體部位管理）：** 透過 CIO 問答確立整體持股水位三級制：

| 狀態 | 整體持股水位 |
|---|---|
| 正常 | 90–100% |
| 警戒 | 70–80% |
| 防禦 | 30–50%（政策最低水位，不設趨近空手之層級） |

資產配置限制方面，CIO 裁定 ETF、個股、現金、產業、地域**均不另設集中度上限**，風險控制完全透過整體持股水位單一閘門執行。

**第四章（部位調整原則）：** 確立「降快升慢」「目標達成即停止」「以狀態轉換為依據，非以價格波動為依據」等原則；降部位（正常→警戒→防禦）採當日或次日完成；回補（防禦/警戒→正常）採分3–5批、1–2週完成，且不因回補距離不同而建立不同節奏規則。

**附件一（部位配置對照表）、附件二（風險管理流程圖）、附件三（與《每日戰情室作業規範》之銜接提案）** 依序完成。

## 五、治理審核第一項：架構一致性檢查

Claude 執行審核，發現整體持股水位數值同時出現於第二、三、四章與附件一共四處，違反「數值單一來源」原則，判定為⚠️建議修正（非阻斷性問題）。CIO 採納，將第二章、第四章之數值複述改為引用第三章，並將此次修正定性為「治理一致性修正（Governance Consistency Fix）」。

## 六、治理審核第二項：與既有文件衝突檢查

Claude 檢查發現三項⚠️：

1. 《每日戰情室作業規範》需增加防禦性減碼例外但書（已有提案，未正式落地）。
2. 《家庭投資中心》未正式掛號於憲章文件地圖（意外發現之既存缺口）。
3. 《正式輸出格式規範》Action Layer 章節未引用《風險管理政策》附件一。

反向依賴檢查通過：《風險管理政策》不依賴《每日戰情室作業規範》即可獨立成立。

## 七、治理里程碑：文件分類制度之建立

由「《家庭投資中心》該不該補掛」一路推演出更根本的治理設計：

- 確立「資料」與「制度」屬不同治理層次：更換持股不需修訂政策，更換政策不需更新持股資料。
- 建立六大文件分類：**憲章、作業文件、研究文件（研究分析／研究架構）、治理文件、知識索引、資料文件**。
- 《AI產業全景圖》經討論不新增第七個頂層分類，改列為「研究文件・研究架構」子類。
- 建立版本判準三級制：治理原則異動＝大版號；文件地圖或分類調整＝小版號；措辭排版＝修訂號。
- 建立《治理決策紀錄》作為獨立治理文件，具「治理解釋功能」——正式文件規定「是什麼」，本文件說明「為什麼如此規定」；收錄原則為僅記錄已正式裁定並生效之決議。
- 建立「引用生效原則」：上位文件先修訂，下位文件後引用；未正式生效之制度，不得由下位文件提前引用。

CIO 將此輪定義為「治理里程碑（Governance Milestone）」，總結四項貫穿性原則：文件依職責分類（非依主題）、制度依生命週期分層（非依內容）、修訂依治理層級決定版本（非依篇幅）、引用依生效順序更新（非依方便）。
